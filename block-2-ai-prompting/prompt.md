# Промпт для генерации чек-листа

**Модель:** ChatGPT-4 / Claude 3.5 Sonnet  
**Дата:** 12 июня 2026

---

## Промпт

```
Ты — опытный QA-инженер, специализирующийся на функциональном и регрессионном тестировании веб-форм в области логистики.

Твоя задача: составить подробный чек-лист для тестирования формы создания заявки на перевозку для MVP продукта «УЛ Лайт».

### Контекст системы

Форма предназначена для создания заявки на перевозку груза между городами России. Это MVP-версия, поэтому приоритет — базовый функционал и валидации.

### Поля формы

1. **Город отправления** (autocomplete/dropdown)
   - Источник данных: база городов РФ
   - Обязательное поле
   - Пользователь вводит первые буквы, система подсказывает варианты

2. **Город назначения** (autocomplete/dropdown)
   - Источник данных: база городов РФ  
   - Обязательное поле
   - Не может совпадать с городом отправления

3. **Вес груза** (числовое поле, килограммы)
   - Обязательное поле
   - Минимум: 1 кг
   - Максимум: 20 000 кг
   - Только положительные числа, допускаются десятичные дроби (разделитель — точка)

4. **Объем груза** (числовое поле, кубические метры)
   - Обязательное поле
   - Минимум: 0.01 м³
   - Максимум: 82 м³
   - Только положительные числа, допускаются десятичные дроби

5. **Дата погрузки** (datepicker)
   - Обязательное поле
   - Нельзя выбрать прошедшую дату (только сегодня или будущее)
   - Формат: ДД.ММ.ГГГГ

6. **Кнопка «Рассчитать стоимость»**
   - Отправляет POST-запрос к API `/api/v2/calculate-price`
   - Возвращает JSON с полем `price` (число в рублях) или `error` (объект с описанием ошибки)
   - При ошибке «маршрут не найден» показывается сообщение: "К сожалению, для данного маршрута расчёт временно недоступен"

### Требования к чек-листу

1. **Позитивные сценарии (happy path)**
   - Успешное заполнение всех полей валидными данными
   - Успешный расчёт стоимости

2. **Негативные сценарии**
   - Попытка отправить форму с пустыми обязательными полями
   - Ввод невалидных данных (текст вместо чисел, отрицательные значения, значения за пределами лимитов)
   - Выбор одинакового города отправления и назначения
   - Выбор прошедшей даты
   - Обработка ошибки API (маршрут не найден, 500-я ошибка сервера)

3. **Граничные значения (boundary values)**
   - Минимальные и максимальные допустимые значения для веса и объёма
   - Граничные значения на 1 единицу меньше/больше лимитов
   - Дата: сегодня, завтра, далёкое будущее

4. **UX и интеграция**
   - Подсказки в autocomplete работают корректно
   - Сообщения об ошибках понятны пользователю
   - Форма не сбрасывается при ошибке API
   - Кнопка «Рассчитать стоимость» блокируется на время запроса (защита от дублирования)

### Формат вывода

Составь чек-лист в виде нумерованного списка с группировкой по категориям:
- Позитивные сценарии
- Негативные сценарии  
- Граничные значения
- UX и интеграция

Для каждого пункта укажи:
- Шаги действия
- Ожидаемый результат

### Дополнительно

Если увидишь потенциальные риски или упущенные проверки, которые важны для логистической формы, добавь их отдельным разделом «Рекомендации».
```

## Пояснения к промпту

### Почему этот промпт эффективен

1. **Чёткая роль**: "Ты — опытный QA-инженер" задаёт контекст экспертизы
2. **Конкретная задача**: не "протестируй", а "составь чек-лист"
3. **Полный контекст**: описание каждого поля, его ограничений, источника данных
4. **Явные требования**: перечислены категории сценариев (позитивные, негативные, граничные, UX)
5. **Формат вывода**: структурированный список с группировкой — избегаем хаоса
6. **Открытая часть**: "Рекомендации" даёт модели возможность проявить "экспертизу"

### Что добавлено для логистики

- Упоминание "логистическая форма" → модель может учесть специфику (маршруты, вес/объём)
- Конкретный API endpoint `/api/v2/calculate-price` → реалистичность
- Обработка ошибки "маршрут не найден" → типичная для логистики ситуация
