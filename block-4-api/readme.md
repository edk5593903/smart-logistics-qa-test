# Блок 4: Тестирование API

Контроллер: **`/api/v2/orders`**  
Стандарты: [Google REST API Guide](https://cloud.google.com/apis/design) · [Microsoft REST API Guidelines](https://github.com/microsoft/api-guidelines/blob/vNext/graph/GuidelinesGraph.md)

## Чек-лист

### 1. POST /api/v2/orders — Создание заказа

| Сценарий | Ожидаемый HTTP-код | Примечание |
|----------|---------------------|------------|
| Успешное создание заказа (valid body) | `201 Created` | Тело ответа содержит `id` созданного заказа, заголовок `Location: /api/v2/orders/{id}` |
| Отсутствует обязательное поле (required field) | `400 Bad Request` | Ответ содержит `error.code`, `error.message` с описанием ошибки |
| Неверный формат поля (e.g. weight = "abc") | `400 Bad Request` | `error.details` содержит `fieldViolations` с указанием поля и ошибки |
| Граничное значение (e.g. weight = 20001) | `400 Bad Request` | Превышение max лимита; описание в `error.message` |
| Отсутствует токен авторизации / неверный токен | `401 Unauthorized` | `WWW-Authenticate` заголовок указывает схему аутентификации (Bearer) |
| Недостаточно прав доступа (forbidden) | `403 Forbidden` | Пользователь авторизован, но не может создавать заказы |
| Content-Type не application/json | `415 Unsupported Media Type` | Запрос отклонён; ответ содержит `Accept: application/json` |
| Падение БД / внутренняя ошибка сервера | `500 Internal Server Error` | `error.code` = `INTERNAL`, не раскрывает детали БД |
| Сервис недоступен (maintenance, overload) | `503 Service Unavailable` | `Retry-After` заголовок указывает время повтора |

### 2. GET /api/v2/orders/{id} — Получение заказа

| Сценарий | Ожидаемый HTTP-код | Примечание |
|----------|---------------------|------------|
| Успешное получение заказа (valid id) | `200 OK` | Тело содержит полный объект заказа |
| Заказ не найден (id не существует) | `404 Not Found` | `error.code` = `NOT_FOUND`, `error.message` указывает ресурс |
| Неверный формат id (e.g. "/orders/abc") | `400 Bad Request` | Ошибка парсинга path параметра |
| Отсутствует авторизация | `401 Unauthorized` | Аналогично POST |
| Недостаточно прав для просмотра заказа | `403 Forbidden` | Например, чужой заказ для данного пользователя |
| Падение БД | `500 Internal Server Error` | Аналогично POST |

---

### 3. GET /api/v2/orders — Получение списка заказов

| Сценарий | Ожидаемый HTTP-код | Примечание |
|----------|---------------------|------------|
| Успешное получение списка | `200 OK` | Тело содержит массив заказов; если пустой — `[]`, не 404 |
| Пагинация (query params: `?page=2&limit=50`) | `200 OK` | Проверить заголовки `Link` с `next`, `prev`, если есть |
| Неверный query param (e.g. `limit=-1`) | `400 Bad Request` | `error.details` с указанием некорректного параметра |
| Отсутствует авторизация | `401 Unauthorized` | Аналогично другим методам |

---

### 4. PATCH /api/v2/orders/{id} — Частичное обновление заказа

| Сценарий | Ожидаемый HTTP-код | Примечание |
|----------|---------------------|------------|
| Успешное обновление (valid body) | `200 OK` | Тело возвращает обновлённый объект |
| Заказ не найден | `404 Not Found` | Аналогично GET |
| Неверная валидация поля | `400 Bad Request` | Аналогично POST |
| Попытка изменить immutable-поле (e.g. `id`) | `400 Bad Request` | `error.message`: "Field 'id' is read-only" |
| Конфликт состояния (e.g. отменённый заказ) | `409 Conflict` | `error.code` = `CONFLICT`, описание причины |
| Отсутствует авторизация | `401 Unauthorized` | Аналогично другим |
| Недостаточно прав | `403 Forbidden` | Например, нет прав редактировать чужой заказ |

---

### 5. DELETE /api/v2/orders/{id} — Удаление заказа

| Сценарий | Ожидаемый HTTP-код | Примечание |
|----------|---------------------|------------|
| Успешное удаление | `204 No Content` | Пустое тело, без содержимого |
| Заказ уже удалён или не существует | `404 Not Found` | Аналогично GET |
| Отсутствует авторизация | `401 Unauthorized` | Аналогично другим |
| Недостаточно прав | `403 Forbidden` | Например, нет прав удалять чужой заказ |
| Конфликт (e.g. заказ в статусе "In Transit") | `409 Conflict` | Нельзя удалить активный заказ |

## Дополнительные проверки

### Стандартные заголовки

- **Content-Type**: проверить `application/json; charset=utf-8` в ответе
- **X-Request-ID**: должен присутствовать в каждом ответе для трейсинга
- **Location**: при `201 Created` должен содержать URL созданного ресурса

### Формат ошибок (по Google Cloud API Design)

```json
{
  "error": {
    "code": "INVALID_ARGUMENT",
    "message": "Weight exceeds maximum allowed value of 20000 kg",
    "status": "INVALID_ARGUMENT",
    "details": [
      {
        "@type": "type.googleapis.com/google.rpc.BadRequest",
        "fieldViolations": [
          {
            "field": "weight",
            "description": "Value 20001 exceeds max 20000"
          }
        ]
      }
    ]
  }
}
```

### Idempotency

- **POST** — не идемпотентен (каждый вызов создаёт новый заказ)
- **GET, DELETE, PATCH** — идемпотентны (повторный вызов не изменяет состояние)

### Rate Limiting

При превышении лимита запросов:

```
429 Too Many Requests
Retry-After: 60
```
